# CampusOS live SQL data snapshot (SQLite dialect)

This file is automatically regenerated by the running Next.js application's SQLite backend after every successful create, update, or delete. It contains the current SQLite schema, seed rows and any subsequently added/edited/deleted data as SQL statements.

- **Live database:** `web/lib/.data/campus.sqlite` — this is the database the Next.js app reads and writes.
- **SQL mirror/snapshot:** `database/live_snapshot.sql` — human-readable, restorable export of that database. It is refreshed by successful application mutations.
- **Download latest snapshot:** Settings → Database connection → **Download current database as SQL**, or `GET /api/database/export.sql`.
- **Restore into an empty SQLite database:** `sqlite3 restored.sqlite < database/live_snapshot.sql`.
- This file is SQLite-specific and **is not** the PostgreSQL schema/seed. PostgreSQL's initial schema and seed remain `database/schema.sql` and `database/seed.sql`.
- Regex CHECK constraints use the app's registered SQLite `regexp()` function. The snapshot disables check evaluation only while replaying data and turns it back on afterward; the app enforces those checks through validation and the registered function.

The snapshot is local runtime data and is intentionally gitignored; it may contain personally entered student/faculty information. Do not commit or publish it. The schema and deterministic bootstrap seed code remain versioned separately in `web/lib/schema.mjs` and `web/lib/seed.mjs`.
